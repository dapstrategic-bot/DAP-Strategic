คู่มืออัปเดตคอร์สหุ้นต้นรอบ — ชุดทดสอบ R01

ข้อมูลหลักอยู่ใน data/tonrob-rounds.json
- currentRoundId ระบุรอบหลักที่ต้องการแสดงปุ่ม “รอบล่าสุด”
- rounds เก็บทุกรอบ ห้ามเปลี่ยน id/slug ของรอบเก่าเพื่อทำเป็นรอบใหม่
- status: open เปิดรับสมัคร / closed ปิดรับสมัคร / draft ยังไม่แสดง
- ราคาปกติ ราคาโปรโมชัน URLชำระเงิน paymentProduct วันเริ่มเรียน รูปแบบ FAQ และสิทธิ์ แยกเป็นข้อมูลของรอบนั้น

ปรับโปรของรอบเดิม
1. สำรองข้อมูลเวอร์ชันเดิมพร้อมวันแก้และคำสั่ง Owner
2. เปลี่ยนเฉพาะข้อมูลที่ Owner ยืนยัน อย่าเติมวันสิ้นสุด ส่วนลด ที่นั่ง หรือสิทธิ์เอง
3. ตรวจชื่อสินค้าและยอดชำระเงินจริงแบบอ่านอย่างเดียว ไม่ทำธุรกรรม
4. ตรวจ Preview และขออนุมัติก่อนเผยแพร่
รายละเอียดที่ผู้เรียนเดิมซื้อไว้ต้องเก็บหลักฐานรุ่นเดิม หากเปลี่ยนเงื่อนไขสำคัญควรแยกรอบใหม่

เปิดรอบใหม่
1. คัดลอก object รอบเดิมหรือดู data/tonrob-round-template.json ตั้ง id และ slug ใหม่ เช่น tonrob-2571
2. เริ่มด้วย status=draft กรอกข้อมูลที่ Owner อนุมัติครบ ห้ามใช้ placeholder เป็นข้อมูลขาย
3. เพิ่ม object เข้า rounds โดยเก็บรอบเดิมไว้ ตัว resolver /products/[slug] รองรับ slug ใหม่อัตโนมัติ
4. เมื่อพร้อมเสนอขาย ตั้ง status=open และ currentRoundId เป็น id ใหม่
5. รัน npm run build ซึ่งตรวจข้อมูลและซิงก์ sitemap-core อัตโนมัติ แล้วตรวจ Preview ก่อนขออนุมัติเผยแพร่

ปิดรอบ
- เปลี่ยน status เป็น closed ไม่ลบ object เดิม
- หน้ารอบเดิมยังอ่านได้ แสดง “ปิดรับสมัครแล้ว” ไม่มีปุ่มชำระเงิน
- หน้ารอบเดิมมีลิงก์กลับหน้าหลักเพื่อดูรอบล่าสุด
- Schema แสดง SoldOut แต่ยังคงราคา/เงื่อนไขเดิมเป็นประวัติ
- หากซ่อนเป็น draft หน้ารอบจะ404 และไม่มีในรายการ/Sitemapหลัง build

ก่อนปล่อยทุกครั้ง
- node tests/tonrob-rounds.cjs
- npm run build
- ตรวจ Products → หน้าหลัก → หน้ารอบ → summaryชำระเงิน
- ตรวจไม่ส่ง purchase จากการคลิก
- ตรวจ noindex ของ Preview และเอา flag Preview ออกก่อน build สำหรับ Production เฉพาะหลัง Owner อนุมัติ
ไม่มีการสร้าง CMS document, recurring job หรือ Automation ในชุดนี้
